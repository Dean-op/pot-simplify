# pot-desktop 精简与性能优化方案

> 基线：`master @ 594d32e`（上游 pot v3.0.7，本地无自定义提交）
> 目标：只保留自己用得到的功能，减小安装包与常驻内存，加快冷启动和划词响应
> 已确认的取舍：翻译只留免登录的 + OpenAI 兼容；OCR 留系统 OCR + 一个云端；砍掉历史记录 / 收藏 / 朗读；**保留**多语言界面、字体选择、配置备份、自动更新、插件系统、本地 HTTP 服务

## 一、动手前必须先处理的三件事

### 1.1 归一化行尾（最高优先级）

`git status` 当前显示 282 个文件 modified，`git diff --stat` 是 56887 增 / 56887 删——增删行数完全相等，说明这不是真实改动，而是工作区 CRLF 与索引 LF 的差异。

不先处理，后面每个 commit 的 diff 都会被 5.6 万行噪音淹没，也没法用 diff 复查"删对了没有"。做法是在仓库根加 `.gitattributes`：

```gitattributes
* text=auto eol=lf
*.png binary
*.ico binary
*.icns binary
*.wasm binary
*.woff2 binary
```

然后 `git add --renormalize .`，单独提交 `chore: normalize line endings`。这一步做完 `git status` 应该是干净的。

在此之前，任何提交都必须 `git add <具体文件>`，**绝不能** `git add .` 或 `git commit -a`。

### 1.2 云端 OCR 选哪家 —— 建议腾讯通用印刷体

留一个云端 OCR 兜底系统 OCR 认不出的复杂版面。候选对比：

| 服务 | 配置字段 | 请求链路 | 每月免费额度 |
| --- | --- | --- | --- |
| **腾讯 `tencent_ocr`（建议）** | SecretId / SecretKey | 前端自算 TC3 签名，一次请求 | 1000 次 |
| 百度 `baidu_ocr` | client_id / client_secret | 先换 access_token，再请求，两次往返 | 1000 次 |
| 火山 `volcengine_ocr` | appid / secret | 依赖 crypto-js 算签名 | 需开通 |

腾讯少一次 token 交换往返，识别延迟更低，字段也最少。如果你已经有百度或火山的 key，直接告诉我换掉即可，改动量一样。

### 1.3 词典发音要不要一起砍 —— 建议保留

你选了砍掉"朗读"。需要区分两条独立链路：

- **TTS 服务**（`services/tts/lingva`）：译文旁边的喇叭按钮，走网络合成语音 → 按你的选择删掉
- **词典发音**（`TargetArea` 第 530 行 `speak(pronunciation['voice'])`）：bing_dict / ecdict 返回的真人音标发音，你要保留这两个词典服务，这个发音是它们结果的一部分

两者共用 `hooks/useVoice.jsx`（30 行，零第三方依赖，纯 AudioContext）。建议**保留 `useVoice` 和词典发音，只删 TTS 服务 + 两个朗读按钮**。如果连词典发音也不要，就一起删，我在方案里标了位置。

### 2.2 架构速记

- **单 `index.html` 多窗口**：`src/App.jsx` 用 `appWindow.label` 从 `windowMap` 里挑组件渲染，5 个窗口（translate / screenshot / recognize / config / updater）共用一份 bundle。另有一个隐藏的 `daemon` 窗口（`daemon.html`），唯一用途是 `window.rs` 里枚举显示器。
- **服务是约定式目录**：`src/services/{translate,recognize,tts,collection}/<name>/`，由同级 `index.jsx` 汇总 re-export。
- **删服务必须改两处**：`src/services/*/index.jsx` 的 re-export，**以及** `src-tauri/src/config.rs` 的 `check_service_available()` 白名单。只改前端会导致 Rust 侧把配置判为不可用并从 `config.json` 里静默删掉。
- **配置读写唯一入口**是 `hooks/useConfig.jsx`，基于 tauri-plugin-store + tauri event 跨窗口同步。
- **Rust 侧模块**：`window.rs`（建窗/取词/截图流程）、`hotkey.rs`（4 个全局快捷键）、`tray.rs`、`server.rs`（tiny_http 监听 127.0.0.1:60828）、`clipboard.rs`（500 ms 轮询）、`lang_detect.rs`（lingua）、`backup.rs`、`system_ocr.rs`。

## 四、第二阶段：性能优化

前面 7 个 commit 是"删"，这部分是"改"，风险更高，建议一项一项验证。按投入产出排序：

### P1 拆分构建产物（收益最大）

**问题**：`src/App.jsx` 顶部静态 import 了全部 5 个窗口组件，Vite 打出一个大 bundle。结果是弹出一个 350×420 的划词翻译小窗，也要解析整个 Config 页面（含所有服务的 `Config.jsx`、Backup 的 WebDAV/阿里云工具、flag-icons CSS）。这是划词响应慢的主因之一。

**做法**：`windowMap` 改成 `React.lazy(() => import(...))` + `<Suspense>`，让 Vite 自然按窗口切 chunk；再在 `vite.config.js` 里加 `build.rollupOptions.output.manualChunks`，把 `react`/`react-dom`、`@nextui-org`、`services/*` 分别独立成 chunk。translate 窗口只需要 `services/translate`，不该加载 `services/recognize`。

**风险**：低。窗口切换本来就是整页替换，Suspense fallback 用一个空 div 即可。

### P2 i18n 按需加载

**问题**：`src/i18n/index.jsx` 把 19 个 JSON 全部静态 import 到 `resources`，348 KB 在主 chunk 里，无论用户界面语言是什么都要解析。

**做法**：`resources` 只内联 `en` + `zh_cn` 作为兜底，其余改成 `i18next` 的动态 `addResourceBundle`——在 `App.jsx` 的 `appLanguage` effect 里 `await import(\`./locales/${file}.json\`)` 之后再 `changeLanguage`。这样多语言界面**功能完整保留**，但只加载实际用的那一种。

**顺带**：`flag-icons/css/flag-icons.min.css`（General 页面的语言选择器用）会把全世界国旗 SVG 打进 bundle。19 种语言只需要 ~15 面旗，可以换成 emoji 国旗（`🇨🇳` 等）直接去掉这个依赖。这是可选项，看你介意不介意 emoji 的显示效果。

### P3 启动路径去串行

**问题**：`src/main.jsx` 是 `initStore().then(async () => { await initEnv(); ...render })`——先等 store 文件读完，再等 4 个 OS 信息 IPC（`type` / `arch` / `version` / `getVersion`）串行返回，才开始渲染。首屏白屏时间 = 两段 IPC 之和。

**做法**：`Promise.all([initStore(), initEnv()])` 并行；`initEnv` 内部那 4 个 await 也并成一个 `Promise.all`。更进一步，`osType` 只影响圆角和窗口控件位置，可以先渲染再补，但那要改 `env.js` 的同步导出语义，收益不大，先做前两步即可。

### P4 修掉 `lang_detect` 每次调用都重建检测器

**问题**：`src-tauri/src/lang_detect.rs` 的 `lang_detect` 命令里，每次调用都执行一遍 `LanguageDetectorBuilder::from_languages(&languages).build()`，22 个语种的模型每次重新构建。这是实打实的 bug —— 划词翻译每输入一次就走一遍。`init_lang_detect()` 预热的那个 detector 是局部变量，用完就丢了，完全没起到缓存作用。

**做法**：用 `once_cell::sync::Lazy`（项目已经依赖 `once_cell`）把 detector 做成全局静态，`init_lang_detect()` 改成触碰一次这个静态量完成预热。

**顺带**：`Cargo.toml` 里 `lingua` 开了 22 个语种的模型 feature，这是二进制体积第一名。如果你只在中/英/日之间翻译，砍到 `chinese, japanese, english, korean` 4 个语种能省下相当可观的体积——**这一项需要你确认常用语种范围**。同时 `lang_detect.rs` 里两个 `languages` 数组和 `match lang` 分支要同步裁剪（注意现有代码有个小 bug：`init_lang_detect` 的数组含 `Ukrainian`，`lang_detect` 的数组不含，但 `match` 里又有 `Language::Ukrainian` 分支）。

### P5 加 Rust release profile

**问题**：`src-tauri/Cargo.toml` 完全没有 `[profile.release]`，用的是 Cargo 默认（`opt-level = 3`、`lto = false`、`codegen-units = 16`、不 strip）。

**做法**：
```toml
[profile.release]
opt-level = "s"      # 体积优先；若感觉运行变慢改回 3
lto = true
codegen-units = 1
strip = true
panic = "abort"
```
`panic = "abort"` 能再省一些体积，但会让 panic 直接终止进程而不是 unwind——pot 里有不少 `.unwrap()`，建议**先不加 `panic = "abort"`**，其余四项先上。代价是编译变慢（`lto = true` + `codegen-units = 1` 大概让 release 构建时间翻倍）。

### P6 收敛 `useConfig` 的事件监听

**问题**：`hooks/useConfig.jsx` 每个 key 都 `listen()` 一个独立的 tauri 事件。`TargetArea` 一个组件里有 10 个 `useConfig`，而 `TargetArea` 是按翻译服务数量渲染多份的——6 个服务就是 60 个监听器，每个监听器都是一次 IPC 注册。

**做法**：两个层次，从易到难：
1. **短期**：把 `TargetArea` 里跨实例相同的配置（`appFontSize`、`autoCopy`、`hideWindow`、`clipboardMonitor`、`translateSecondLanguage`）提到 `Translate/index.jsx` 读一次，用 props 或 jotai atom 往下传。改动小、风险低。
2. **中期**：给 `useConfig` 加一个模块级注册表，同一个 key 只注册一个 tauri listener，多个组件订阅同一个回调。这是通用改造，收益覆盖整个应用，但要小心 `syncToStore` 的 debounce 是 per-hook 实例的，合并时别把不同组件的写入互相 debounce 掉。

### P7 daemon 窗口改懒创建（需实测）

**问题**：`tauri.conf.json` 的 `windows` 数组在启动时就创建了隐藏的 `daemon` 窗口。它唯一的用途是 `window.rs::get_current_monitor()` 里枚举显示器（Tauri v1 的 `AppHandle` 没有 `available_monitors`，必须借一个 Window）。在 Windows 上一个 WebView2 实例大概占 30-60 MB，而 pot 大部分时间是驻留托盘不干活。

**做法**：`get_daemon_window()` 里已经写好了"找不到就创建"的兜底分支，所以从 `tauri.conf.json` 的 `windows` 里删掉 daemon 配置就能变成懒创建。注意这只是把开销**推迟**到第一次划词，之后窗口仍然常驻；要真正省内存得在用完后 `close()`，但那样每次划词都要重建 WebView，可能反而变卡。

**建议**：先只做懒创建，用任务管理器实测"启动后驻留托盘"和"用过一次之后"两个状态的内存，再决定要不要 close。

### P8 tray.rs 去重（可选，收益偏小）

11 个 `tray_menu_xx()` 函数结构完全一样，只有字符串不同，占了 27 KB 里的绝大部分。可以改成一个 `tray_menu(labels: &TrayLabels)` + 一张语言到字面量的表。这是代码可维护性收益，编译后体积省得不多，优先级放最后。

### 明确不做的优化

- **`clipboard.rs` 的 500 ms 轮询**：看着刺眼，但循环在 `clipboard_monitor` 为 false 时会 `break` 退出，默认关闭时零开销。不值得改。
- **`framer-motion`、`crypto-js`、`uuid`、`nanoid`、`react-beautiful-dnd`**：分别是 NextUI 的 peer 依赖、插件系统注入的 utils、yandex + lang_detect 用、多处生成 id 用、服务列表拖拽排序用。都还在用，不能删。

## 五、验证方式

我这边的 Linux 沙箱**没有 Rust 工具链，也没有 pnpm 和 `node_modules`**，所以 `cargo check` 和 `pnpm tauri build` 必须在你的 Windows 上跑。我能在沙箱里做的是静态检查（引用是否有残留、JSON 是否合法、白名单是否对齐）。

每个 commit 之后建议按这个顺序验证：

1. `pnpm build` —— 确认前端没有悬空 import（删服务最容易漏 `index.jsx` 的 re-export）
2. `cd src-tauri && cargo check` —— 确认 Rust 侧白名单改动没编译错误
3. `pnpm tauri dev` —— 冒烟测试：划词翻译弹窗、输入翻译、截图 OCR、托盘菜单、设置页 8 个 tab 都能打开
4. 特别检查一次：删服务后**打开一次设置页的"服务管理"**，确认 `check_service_available()` 没有把你还在用的服务误清掉（这是最容易出问题的地方，前端目录名和 Rust 白名单里的名字不一致，比如目录叫 `tencent` 但白名单里写 `tencent_ocr`）

两个阶段之间跑一次 `pnpm tauri build`，记录安装包体积做前后对比。

## 七、明确不动的部分

按你的选择保留，本方案不碰：多语言界面（19 种全留，只改成按需加载）、字体与备用字体选择（`font-kit` 依赖保留）、配置备份（WebDAV / 阿里云 OSS / 本地，`reqwest_dav` + `zip` + `walkdir` 保留）、自动更新（`updater` feature 和 Updater 窗口保留，注意 endpoint 仍指向上游 pot-app 仓库，自建版本收不到更新也不会误升级）、外部插件系统（`invoke_plugin` + `install_plugin` + `run_binary`）、本地 HTTP 服务（60828 端口）、划词/输入/截图 4 个全局快捷键、剪贴板监听。

### 一个安全提醒（不在本次范围，但值得知道）

`src-tauri/tauri.conf.json` 的 allowlist 几乎全开（`fs-all`、`shell-all`（`open` 放开 `.*`）、`http-all` 放开 `http://**` 和 `https://**`），CSP 也是 `default-src *` + `script-src 'unsafe-eval'`，加上 `invoke_plugin` 用 `eval()` 执行插件目录里的 `main.js`、`run_binary` 可以执行任意命令、60828 端口的 HTTP 接口没有任何鉴权（本机任何进程都能 POST `/translate` 触发窗口）。

这是上游为了支持任意插件而做的设计取舍，自用没问题。但如果哪天你想收紧，最有效的一步是把 `shell.open` 的 `.*` 改成具体的 URL 白名单，其次是给 60828 加一个 token。我没把它排进本次方案，因为你明确要保留插件系统和 HTTP 服务，收紧会和它们冲突。
