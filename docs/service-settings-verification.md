# 服务设置修复验收

日期：2026-11-08。基线：`e6dd3af` / v3.2.0。分支：`codex/service-settings-fixes`。
本次不修改版本号、不发布安装包、不推送远端。

## 改动边界

-   共用 `ServiceConfigForm` 和 `useServiceSave` 管理验证、保存、防重复提交及卸载后的回调。
-   `useConfig` 的非同步模式只读取独立草稿，不自动写入默认配置、不订阅外部覆盖事件。
-   显式保存等待存储和通知完成；同一键的写入/删除按顺序执行，取消旧防抖写入，保存失败恢复存储内存值。
-   OpenAI 和视觉 OCR 共用模型列表加载逻辑，忽略过期请求，不新增生产运行依赖。
-   使用 [React 官方仓库](https://github.com/react/react) 提供的 MIT 许可 `react-test-renderer@18.3.1` 测试真实 hook，与现有 React 版本一致。

## 自动化验证

-   `pnpm test`：24 项通过，其中 13 项服务设置测试、11 项既有 Markdown/流式翻译测试。
-   服务测试使用真实 React hook 和 Vite SSR，仅替换 Tauri 存储、事件、HTTP 边界；覆盖草稿、默认值、保存顺序、错误恢复、重复提交、卸载、删除竞态和过期模型列表。
-   新增草稿等前五项测试在旧实现上失败；保存失败和已开始写入后删除两项在补充修复前失败，修复后通过。
-   `pnpm build`：前端生产构建通过；`cargo test --manifest-path src-tauri/Cargo.toml --locked`：5 项二维码回归通过。
-   Prettier 和 `git diff --check` 通过。Browserslist 提示兼容性数据库较旧，不影响本次构建；未借此扩大依赖升级范围。

## 真实桌面验证

通过独立标识启动真实 Tauri 应用，使用 WebView2 CDP 调试其 `config` 和 `translate` 原生窗口，不使用普通浏览器模拟 Tauri API。

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS='--remote-debugging-port=9223'
node node_modules/@tauri-apps/cli/tauri.js dev --config '{"tauri":{"bundle":{"identifier":"com.pot-app.service-qa"}}}'
```

测试配置位于 `%APPDATA%\com.pot-app.service-qa`，未修改用户正常的 `com.pot-app.desktop` 配置。清除 CDP 默认视口覆盖，以原生窗口尺寸操作。
OpenAI/OCR 验证使用本地 HTTP 固定响应和虚拟密钥；模型列表提供延迟响应，验证取消和端点切换。

| 场景                              | 结果                                                                     |
| --------------------------------- | ------------------------------------------------------------------------ |
| 选择服务后进入配置                | 只有一个弹窗，不再叠加选择弹窗                                           |
| Google 自定义地址清空、取消       | 空值保留，取消后没有新增存储键                                           |
| OpenAI 新增、编辑、取消、重新打开 | 保存后列表更新；取消恢复已保存名称和密钥                                 |
| 同供应商多个实例                  | 分别读取各自的密钥和名称，不串用配置                                     |
| 旧 OpenAI 配置缺字段              | 补全 model/stream/thinkingMode 等字段，保留禁用状态和自定义 Prompt       |
| 删除 Prompt 后编辑剩余项          | `user` 角色保持不变，没有被改为 `system`                                 |
| HTTP 401 后重试                   | 弹窗和草稿保留，不插入列表；恢复成功响应后可保存                         |
| 重复提交、测试期间取消            | 只发出一次验证请求；禁用表单控件；取消后没有实例或孤立配置               |
| 模型列表请求后修改地址            | 旧响应不显示，新端点可加载并选择 `qa-model`                              |
| 无需配置的 ECDict、系统 OCR       | 配置保存到新增的实际实例键，而非固定服务名                               |
| 视觉模型 OCR 新增与编辑           | 原生 HTTP 非流式验证通过，保存、重开、改名正常                           |
| 已打开的翻译窗口                  | 服务改名后原窗口显示新名称；编辑保存发出列表刷新事件                     |
| 测试等待期间发生其他排序更新      | 修复前被旧列表覆盖，修复后保存保留新顺序                                 |
| 延迟落盘时关闭并重新打开弹窗      | 修复前旧回调关闭新草稿，修复后新弹窗和草稿保留                           |
| 拖拽、启用、删除、重载            | 键盘拖拽上移有效；启用状态和顺序持久化；切换后立即删除不会恢复已删除实例 |

修复后的上述操作未捕获到应用 `pageerror`。已有词典服务在翻译窗口烟测中实际查询了 `hello`。

## 限制

-   测试期间取消会丢弃草稿；已经进入落盘阶段的保存会完成配置和列表更新，但不再操作后来打开的弹窗。
-   磁盘写入失败使用异步存储测试替身验证；延迟落盘桌面测试仅延迟真实 `store.save()`，没有制造实际磁盘故障。
-   未使用真实付费供应商密钥做连通性测试，也未重新构建安装包。
-   同键队列解决当前 WebView 内的写入竞态，不提供跨进程事务或数据库级原子性。
